# Architecture

DesktopTools is one WPF executable, with Windows Forms used for the tray icon. `App` owns the single-instance mutex/activation signal; `AppController` coordinates settings, windows, shortcuts and lifecycle. Closing settings keeps the tray alive; Quit disposes owned resources.

`Core` contains the annotation document, bounded undo/redo, settings and explicit Hidden / Draw / Interact / Capture states. A session stays attached to one monitor. Disabling drawing or a display topology change dismisses its input surface safely. Annotations are monitor-local logical coordinates.

`UI` renders the same annotation model both live and into output. The canvas and palette have separate top-level HWNDs. Draw takes local pointer input; Interact adds transparent/no-activate styles and restores foreground focus. The transparent canvas never receives the optional Acrylic backdrop. Settings and controls use native material when supported and an opaque fallback otherwise.

`Native` isolates monitor enumeration, physical pixel placement, GDI capture, display affinity, foreground helpers, per-user startup, profiles and RegisterHotKey. Hotkey replacement retains existing combinations, acquires every new combination before retiring old registrations, and commits action mappings only after success. Swapping two actions does not release either combination.

The screenshot pipeline hides app windows, waits for desktop composition, captures physical desktop pixels once, restores UI, and composites annotations once before cropping/output. Monitor bounds may have negative origins. Selection and annotation coordinates are local DIPs; crop coordinates are local physical pixels. PNG export dimensions follow the pixel crop, not virtual desktop origins.

`Extras` contains transient laser/spotlight windows, pinned captures and screenshot redaction. On first load the screenshot editor opens centered at 75% of its actual monitor working-area width and height, using physical pixels for placement and per-axis DPI conversion for WPF sizes. Later resizing is retained for that editor instance; image pixels and zoom are unaffected. Redaction exports a flattened copy while leaving the original image unchanged. Solid covers render last; pixelation and blur stay within their region bounds. The editor preview and export share the same rendering path, and accepted suggestions form a single undo step.

Auto Redact uses installed Windows OCR locally. Positioned OCR enlarges bounded overlapping tiles by two, and retains a separate three-times reading for tiny text. Tile dimensions remain within the Windows recognizer limit; each reading has at most 64 tiles and combined layouts remain limited to 10,000 words. Both readings map word boxes back into physical source pixels. Native OCR line membership keeps punctuation and short fragments with their field; repeated tile lines are merged geometrically. A pure detector joins adjacent identifier fragments, covers complete labelled values and tolerates measured OCR separator/digit confusions while validating numeric candidates. It coalesces intersecting findings and returns category labels without exposing values. Installed English OCR supplements machine values, and installed app-language OCR supplements localized labels when context categories are enabled. Duplicate recognizer languages are skipped. No OCR transcript is logged or persisted. Crop-local findings are offset into full-image coordinates before creating editable covers. Hide all found creates all suggested covers in one undo step without changing output until the user copies or saves.

Phones use a spaced line reading so compact fragment joining does not remove their format. If a context label lacks a value in one reading, the detector searches a Y-sorted index for nearby, vertically aligned value boxes from complementary readings, stopping at a large horizontal gap. Combined recognizer layouts keep distinct line indexes and use the same word/character limits; exceeding aggregate limits requests cropping. An email-shaped asterisk substitution is a suggestion, so false positives remain possible and require user review.

Two-column table detection accepts complete standalone labels without colons, including User ID and numbered nicknames. Native lines are split into cells at large horizontal gaps. A Y-sorted lookup associates a label with a same-row value within twenty label heights; contiguous value fragments are joined across native lines, stopping at a four-height gap. A second nearby row must align both label and value columns. Peer lookup is bounded to neighbouring rows, and all categories may corroborate table geometry while only enabled categories produce suggestions. Email table labels also recover disconnected local-part prefixes. Ordinary password prose is not a table label. Isolated unpunctuated labels and tables with unusual spacing may still need manual covers; matching remains a suggestion rather than a guarantee.

Very small primary words (height at most nine source pixels) also trigger independent narrow-row OCR at 3x. Narrow images retain full-width strips with ten pixels above the word and 32 pixels of additional height. On images wider than 1600 pixels, strips retain an extra top context pixel; actual pixel detail selects occupied horizontal cells and refines their edges with a ten-pixel margin, including words wholly omitted by primary OCR. OCR boxes map both X and Y back into source coordinates. The row budget allows at most 256 regions/tiles and six million source pixels per recognizer, with 10,000 combined words still enforced. Empty desktop margins therefore do not multiply supplemental work across every monitor tile. Row discovery and reads check cancellation, and an exceeded budget requests cropping instead of returning a successful partial scan. Larger strips, inversion, thresholding and 4x/6x sampling did not recover all 5–6px numeric glyphs in a generated stress case; this remains an OCR limitation, not a reason to accept malformed IPs.

Credential suggestions also include dotted password-shaped tokens (ordinary email-shaped values remain email suggestions), and 8–128 character password-shaped tokens with at least two letters, two digits and a hard symbol (`!#$@&*?`). Narrative password wording can corroborate shorter values with internal symbols. A mixed-case prefix ending in `!` is accepted only beside password wording and a strong continuation on the next nearby row. Direct and complementary prose lookups exclude ordinary URL spans, validate complete token syntax and avoid tested password-policy punctuation. This heuristic can still flag non-secret strings; plain unlabelled words do not reliably qualify. Detached symbol boxes are joined only within a small physical gap. Known prefixed key matching tolerates a measured five-for-s substitution. IPv4 octets remain validated after narrow digit normalization and allow trailing sentence punctuation.

Wrapped `sk-` and `sk-test-` prefixes at a row end can attach to an ASCII continuation on the immediately following physical row, including complementary readings of that row. Continuation geometry is relative to its prefix rather than total image width, so moving the same content within a monitor preserves the rule. Prefix and continuation receive separate covers; ordinary word spacing, terminal punctuation and later rows stop extension. Phone regex candidates are separated at validated IPv4 spans while retaining character offsets, so an adjacent real phone remains detectable. Padded findings merge only with substantial vertical overlap rather than bridging neighbouring rows.

For small primary OCR rows, `OcrGapRegions` plans bounded crops of large internal gaps where a word may have been omitted. Independent 3x reads map both X and Y back into the source image. Each recognizer allows at most 64 gap crops, with cancellation, source clipping, tile/pixel limits and the combined word budget still enforced. An exceeded budget asks the user to crop instead of declaring a partial scan clean. These supplemental reads remain local and transient.

Automatic review is opt-in through `AppSettings.AutoRedact`. `AppController` keeps a captured bitmap pending until a review window successfully copies or saves its flattened result. The pending bitmap does not update `LastCapture`, history, clipboard, pinned captures or capture notices. Save cancellation, output failure and review closure preserve the previous published capture. Each editor owns a cancellation token and revision-based review state; edits invalidate findings, and stale or closed scans cannot enable export. Ordinary editors expose manual detection independently of the automatic preference.

Unlabelled handle lists use standalone ASCII underscore identifiers or mixed-case names ending in a digit, with at least two nearby vertically distinct aligned rows. Their physical font heights determine spacing tolerances; adjacent suffix cells are joined and overlapping complementary boxes extend geometry without duplicating valid text. Known labels and corroborated table-label columns are excluded. This remains a conservative suggestion heuristic: plain names, isolated aliases and unusual OCR spellings may not qualify, and identifier-shaped ordinary text can still produce false positives. Input limits and local-only processing remain the same. Telephone matching also tolerates the measured e-for-zero OCR substitution while validating digit counts and excluding dates/IPs.

Profiles copy only explicitly listed tool, presentation and shortcut preferences; startup, theme, monitor, save destination and palette coordinates remain general settings.

Settings and profiles use versioned JSON and atomic replacement. Malformed settings are retained for diagnosis before defaults are restored. Future schemas are not silently overwritten. There is no backend or persistent annotation storage. Global hooks and global input blocking are not used.

Wrapped credential continuation uses the nearest preceding text on the same physical row to establish a paragraph boundary, including when Windows OCR separates the prefix into another native line. A Y-index restricts context and continuation searches before per-column filtering, so unrelated sidebar rows do not interrupt a body-column key. Intervening prose within that column still stops continuation. Mixed-case password prefixes with both an internal hard symbol and a final hard symbol can attach to a four-to-twelve-digit next-row tail; URL-overlapping prefixes are excluded. The pieces remain separate editable covers.
